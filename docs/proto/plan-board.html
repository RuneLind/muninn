Mimir Plan Boardprototype

All 181 plans in mimir/plans/, filed by plan_status, priced against what comparable work actually cost in the claude-usage ledger. Real data, read . Drag a card, or nudge it with ▲▼, to rank a column by hand; the ↗ opens the plan itself. Priority, ranking and column moves are local only — nothing writes back; the tray shows the patch it would make.

Where the numbers come from

  • Status, tags, follow-ups — the plan file's own frontmatter.
  • Cost, hours, PRs, findings — claude-usage GET /api/plans, which attributes a session to a plan on 3+ path references or a title hit.
  • Estimates — median $/PR of shipped plans in the same repo, × the PR count the plan declares.

Proposed vs Ready

mimir's own legend: proposed is "written; awaiting go/no-go", ready is "reviewed / plan-review-looped; safe to dispatch". So Ready is not a queue position — it is a gate: someone said yes, and the plan survived a review. Today 49 plans sit in Proposed against 3 in Ready, which is what an unused gate looks like. Keep both — that gate is exactly what an agent would need to pull work unsupervised — and use the ranking here to say which Proposed plans should go through it next.

What this prototype does not do

  • Write anything. Drags and priorities live in localStorage.
  • Know a plan's size when it declares no PR slate — 47 of 60 active plans don't, and those cards say so.
  • Split cost between two plans a session worked at once.
