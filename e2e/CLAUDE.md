# Browser checks (e2e)

<!-- moved out of the root CLAUDE.md by /doctor on 2026-10-13 -->

Anything that has to be verified **in a browser** goes through Playwright.

- **A spec in `e2e/`** is the default for acceptance. `bun run test:e2e` runs every `e2e/*.spec.ts`; each spec's header comment states what it proves that a unit test cannot, the fixture it builds and why it boots its own muninn (or several, or restarts one mid-file) — read the header of the nearest spec before writing a new one. `playwright.config.ts` owns its own server on **3011** with `reuseExistingServer`, so a dev server already on that port is reused as-is. Don't start a server by hand for the suite; let the config decide.
- **Every spawned muninn gets `e2eEnv()`** (`e2e/e2e-env.ts`), spread after `...process.env` and before the spec's own overrides. It blanks two classes of ambient value: the platform tokens (a second long-poller on the real token knocks the production bot off Telegram, 409 getUpdates) and the **instance-profile flags** — `MUNINN_WIKI_READONLY`, `SYNC_REPOS`, the `MUNINN_AUTH` family. It also sets `RESEARCH_MCP_PORT=0`, so each spawned muninn takes a free port for its research MCP server instead of 9190, which a parallel spec or the developer's own muninn already holds. `WIKI_READONLY_ROOTS` is deliberately NOT among them: it is a per-root permission GUARD, not a profile flag, and blanking it while `WIKI_EXTRA` still registers the root leaves that wiki writable and egress-reachable (see `src/test/ambient-env.ts`). The names are the same list `bun test`'s preload clears (`src/test/ambient-env.ts`), because the failure is the same: the mini carries `MUNINN_WIKI_READONLY=1`, so its spawned servers came up read-only and the suite was green on the laptop and red there. **A blank must be an explicit `""` assignment, never a delete** — the child re-reads `.env` itself, and an absent name is exactly what makes Bun fall back to the dotenv line.
- **Ports come from `e2e/ports.ts`, never a literal.** Spec files run in parallel and most boot their own muninn; two files both picked 3042 and the loser's requests were answered by the winner's server (an empty page list, not a bind error). `e2e/ports.test.ts` — a `bun test`, in the `bun run test` chain — fails on a duplicate value and on a bare port literal left in a spec.
- **A spec that needs a BOT of its own creates it under `MUNINN_BOTS_DIR`, never under `bots/`.** That env var is the root discovery walks (`resolveBotsDir`, `src/bots/config.ts`; default unchanged, and it is in `AMBIENT_INSTANCE_ENV`, so a blank `""` from `e2eEnv()` means "the default", not the working directory). `bots/` is state the developer's own `bun run dev` reads: a hard-killed spec leaves its throwaway behind, and there is no ordering to hide behind — discovery iterates raw `readdirSync`, which is not alphabetical, so `resolveSummarizerBot`/`resolveResearchBot`'s positional fallback can land on a bot pointing at a dead port. Under local parallel workers, other specs' servers discover it too. `e2e/summaries-vimeo.spec.ts`, `summaries-prompts`, `summaries-rerun` and `gardener-backlog-error` use it (an OS temp dir via `mkdtempSync`).
- **A fresh database is not enough.** `bun run db:seed:e2e` inserts the one user, two threads and one trace that `chat`/`inspector`/`traces-waterfall` need; without it those specs fail (nothing to select) or, worse, **skip themselves green**. CI runs it; a developer's own DB already has content.
- **`playwright-cli`** (skill: `~/.claude/skills/playwright-cli/`, global `@playwright/cli`) drives a page interactively for exploration — snapshot refs, `console`/`network` readout, headless by default. Promote whatever it proves into an `e2e/` spec; evidence left in a transcript is not a test. Its scratch (`.playwright-cli/`) is gitignored.
