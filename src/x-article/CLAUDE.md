Path: `src/x-article/`

X/Twitter summarization (backs `x-article-routes.ts` + Chrome extension). Two paths into the same job store + `x-articles` collection: `summarizer.ts` (pasted text) and `video.ts` (X video posts). `video.ts` is a SPEC over the shared short-video job (`src/video/short-video.ts`) rather than a summarizer of its own: 3-hour cap, duration-scaled timeouts, ingest + dedup keyed on the bare status URL via `canonicalXStatusUrl`/`extractXStatusId` so media-slot/query variants can't double-capture, and no degraded-frame-Reads warn (the TikTok spec's, deliberately not inherited). Same frames pre-flight as TikTok (`shortVideoCaptureBlocker`, `src/video/short-video-kinds.ts`): with frames on (the default) the route checks the connector's `supportsExtraDirs` and, on claude-cli, the CLI version (`restrictedCliBlocker`, ≥ 2.1.303 for `--restricted`), and answers 503 with a plain-sentence `error` (no `code` field, unlike YouTube/Vimeo's `frames_unsupported`/`cli_too_old`) before a job exists; `frames: false` is never blocked. Same yt-dlp requirement and the same `kind` picker (`GET /api/x-articles/video-options`).

## The article's links

**The text path keeps its links** (plan muninn-summary-links, PR 2). The extension builds the article's text with the shared markdown walk (`src/summaries/html-to-markdown.ts`, emitted into `extensions/x-article/html-to-markdown.js`), so an anchor arrives as `[text](href)`; a `t.co` anchor whose text spells the expanded URL (X renders it partly in hidden spans) arrives with that URL. Server-side, `summarizer.ts` calls the shared text pair (`src/summaries/text-links-run.ts`): `prepareTextLinks` resolves the remaining `t.co` URLs and every bare known-shortener URL (`bit.ly`, `lnkd.in`…) one hop each through `safeResolveRedirect` (at most 40 lookups in all, the bare shorteners counted; a `t.co` whose target is a known shortener gets one more hop, and a URL reached both ways is looked up once), under ONE 10 s budget for the whole post, replaces it in the text the model reads, and numbers the candidates (`text-links.ts`: X self-links and media, unresolved `t.co`, the post's own URL and social profiles dropped, every other URL a candidate, deduplicated, capped at 40). With a candidate, the system prompt gains the `LINKS:` step (`linksStep` on `xArticleSystemPromptPieces`) and the user prompt the `## Links in the text` list; with none, both are byte-identical to before. After the call, `prepareLinksAnswer` strips the `LINKS:` line and `finishTextLinks` renders the `## Links` section from the model's pick ONLY — a text has no by-rule placement — with a GitHub repo line where the lookup answers. The X VIDEO path sends no post text, so its links are reachable only through PR 3's Find links. The live check of X's anchor markup is the owner's step after the extension reload.
