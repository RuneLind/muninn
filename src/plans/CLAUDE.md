## The `Plans` entry from the root `CLAUDE.md` module table

The `/plans` board over mimir's `plans/` directory, priced from the claude-usage ledger. `source.ts` reads the frontmatter + `queue.yaml` off disk, `ledger.ts` proxies claude-usage's `GET /api/plans`, `estimate.ts`/`join.ts` price and join them, and `board.ts` assembles the payload `GET /plans` embeds and `GET /api/plans/board` serves (route: `dashboard/routes/plans-routes.ts`, view: `dashboard/views/plans-page.ts`, client rules in the DOM-free `board-client-pure.ts`). **Three write endpoints** edit the mimir wiki — `POST /api/plans/priority` (one plan's frontmatter `priority:`, through `writeWikiPage`'s no-log mode), `POST /api/plans/status` (the drawer's archive/restore: `plan_status` + a stamped `status_date`, same no-log path; same-status is a noop that leaves the date alone; the ROUTE accepts every enum value, `shipped` included — the drawer's refusal to un-ship is a UI-only invariant) and `POST /api/plans/order` (`plans/queue.yaml`, through `src/plans/write.ts`). All compare-and-swap on sha256 and return the new hash; an order POST MERGES (a posted column replaces that column, an absent one is preserved, `[]` un-ranks); none of them commits, since mimir is in the repo-sync loop in `wiki` mode and the loop is the committer. The fence rules the priority transform lives by, the three states of `queue.yaml`'s base hash and the wire shapes are in the module docs (`src/plans/{frontmatter,write}.ts`, `dashboard/routes/plans-routes.ts`) and the no-log-mode section of `src/wiki/CLAUDE.md`. **The board itself writes** (`board-writes.ts` — the pure gate/request/response rules; `views/components/plan-board.ts` — the fetches): a drawer priority click and a ▲▼ nudge POST straight to those routes, adopt the hash the 200 answers with, apply nothing optimistically, serialize (one write per card, one chain for the queue) and surface a 409 — or any 400/404, which is how a plan retired or renamed upstream reads — as a stale-board message with a Reload that refetches `/api/plans/board`. **A write in flight does NOT disable the ▲▼** (the click queues on the chain and is computed from the order the previous write landed; the column shows a "saving…" marker instead, and focus stays on the button), while a STALE board does: a standing reload-worthy failure disables the nudges and the affected card's priority buttons until Reload, and the standing message is cleared only when a write LAUNCHES. A Reload waits for both write chains, then adopts a fully parsed payload wholesale (`parseBoardRefresh` — all of it or none) and clears only the messages that predate it. There are **three write modes**, and the `localStorage` draft (`muninn.planboard.draft.v1`) is retired PER AXIS — the priority half the moment priorities are server-owned, the order half the moment ranking is: `MUNINN_WIKI_READONLY=1` keeps both halves and renders one banner with every control DISABLED-not-absent (a 403 flips the page into that state mid-session AND folds the refused click into the draft); an UNREADABLE `queue.yaml` (`hash === null`) turns ranking off with its own reason — on a readonly instance too — while priority stays writable on a writing one; otherwise the server owns both axes and the draft key is cleared on load and never written again. The masthead's write-mode sentence is rendered from the capability on BOTH ends (`writeModeSentence`), so a mid-session flip cannot leave it claiming the board writes. **A column's hand order is a ranked PREFIX, not a permutation** — ▲ on an unranked card appends it, ▼ on the last ranked card un-ranks it (and the last un-rank DELETES the file), so ranking six cards in a 49-card column leaves 43 degrading on priority-then-age. Only the four active columns are rankable: `queue.yaml`'s grammar has no key for `shipped`/`followups`, so the ▲▼ there are disabled rather than posting a 400. View state (scope/sort/query/repo/priority) lives in the URL. **Every meter COUNT is over the cards the current scope renders** (`cardsInScope`) — a follow-ups tile counting a column no scope shows is a number the reader cannot check, so it renders `—` rather than `0` there — while **Spent to date stays corpus-wide** (all scopes, filters applied) and says so in its note, since under the default scope no terminal column is on screen at all. An unreachable ledger hides the MONEY only — columns, priorities and order still render, repo families fall back from PRs to slugs (the banner says so), and neither route can 5xx: the assembly AND the render are caught.
